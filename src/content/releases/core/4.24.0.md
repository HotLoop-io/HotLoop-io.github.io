4.24.0 makes a HotLoop screen a P&ID, brings a CODESYS PLC's own alarms into the alarm list, and closes two gaps that read wrong: a script run that never ended and a data volume that would not read.

## What changed

- **Screens are P&IDs.** Drop tanks, pumps, valves, heat exchangers, filters, instruments and junctions on a symbol page, then drag from one connection point to another. The pipe lays itself in right angles around everything on the page, tees off with a junction where you drop it on another pipe, and re-routes while you move a symbol. Every pipe carries its medium, each with a color, a code and a line pattern, so color is never the only carrier, and moves with its tag or a rule. A P&ID saves, exports and imports in the same screen file.
- **View controls on every symbol page.** Zoom, pan, a mini-map and a grey high performance view.
- **A CODESYS PLC's own alarms show in HotLoop's alarm list.** A CODESYS device reads the alarms its PLC's alarm manager holds, active, waiting to be acknowledged, and acknowledged while the condition still holds, and an acknowledge made in HotLoop goes back to the PLC. It needs the HotLoop Alarms library and one block in the project.
- **The box's data volume always reads.** The box-health `data_util_pct` tag reads the volume the data folder will be made on, so a box with nothing mounted under `/data` no longer reads bad.
- **A script run always ends.** When the database refuses the write of a run's end, HotLoop asks again, up to five times with a short wait between.
- **UniFi Protect, Access and SmartPower PDU outlets are shipped on the roadmap.** They arrived as devices in 4.23.6.

## Upgrade

A plain `helm upgrade`. No migration and no new secret. A symbol page with no pipes is drawn as before. This release builds the amd64 image, and the arm images follow in the next version.
