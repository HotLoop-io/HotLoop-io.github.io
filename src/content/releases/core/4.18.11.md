PostgreSQL won't open another major version's data directory, so a bare image change would have left every existing box with a database that can't start. A script copies your data across with pg_upgrade before the database starts, proves the new server opens it, and only then swaps the names. The old directory stays as pgdata.pg16, which is your way back, and it is yours to delete. Proven on real 4.18.10 data for the Gateway, Edge and IoT, on the chart and on Quadlet, with every row kept."

  - "SNMP v1, v2c and v3, read-only, with no default community. BACnet/IP, read-only, for building controllers and meters. HotLoop never sends a SET and never writes a BACnet property. Proven against net-snmp and recorded BACnet frames in the lab, not on a physical switch or controller."
  - "Kiosk sign-in: a panel asks for a PIN or a badge, every write through the gate is that person's, and an idle panel signs out on the page and on the server."

All four products ship from this tag in lockstep, so the Edge Relay is 4.18.11 too, with no database and nothing to do. This is the release where the database engine changes under a running plant, so the first thing to read is the upgrade, not the feature list: [Upgrading from 4.18.10](https://docs.hotloop.io/gateway/upgrading/#upgrading-from-41810) says what the first start does, how long to expect it to take, and the one way back that isn't a plain rollback.

What isn't proven yet. The directory swap back after a rollback is documented, not run by a test. IoT's plain PostgreSQL directory has no TimescaleDB extension in it, so the move up a product on a 17 volume hasn't been run again on 17. SNMP and BACnet/IP have not touched a physical switch, UPS, PDU or controller, so treat the first read of a real one as commissioning and compare the probe's sampled values with the device's own display. Everything the 4.18.10 notes list as unproven still is: Edge and IoT as live Quadlet units under systemd, a real Pi, and the 32-bit arm images on real hardware.
