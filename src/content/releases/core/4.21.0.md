  - "The deprecated security policies Basic128Rsa15 and Basic256 are off by default, on new installs and on upgrades. A legacy client connects again with HOTLOOP_OPCUA_SERVER_ALLOW_DEPRECATED_POLICIES=true."
  - "The CODESYS alarm import reads an Outside range alarm, which comes across as two alarms at the lower and upper limits."
  - "There are five new MCP tools, 133 in all."
breaking:
  - "A client of the OPC UA server that speaks only Basic256 or Basic128Rsa15 stops connecting after the upgrade until you move it to Basic256Sha256 or set the legacy switch."

One migration, 0027, adds the `user_certificates` table, which holds public certificates only and is in the backup. A plain `helm upgrade` or the Quadlet auto-update takes it. A rollback to the previous release was not tried with the new table in place.

What is not proven: the OPC UA server was tested against gopcua, HotLoop's own driver, and python asyncua 2.1.0 in a container. It was not tested against UaExpert, KEPServerEX, WinCC or Ignition's X.509 login. A CA that vouches for client certificates is not built, only the registry.

This build is amd64 only, and `stable` keeps the arm images it holds. The next release is one small version bump that builds the arm images.
