4.19.0 and 4.19.1 were tagged and never published, so nothing named 4.19.0 or 4.19.1 exists, and `stable` never moved to either. 4.19.0's release run died in its Test job, before any image, chart or release was made, because the runner's environment file refused a multi-line CA certificate. 4.19.1 added the fix and one more, and was skipped before it released. This is the first release with everything their notes list, plus one new thing, the `hostNetwork` setting on the charts.

All four products ship from this tag in lockstep, so the Edge Relay is 4.19.2 too. Two things change what an existing plant does, so read them before you touch a running one: agents over MCP can write now, and a value you write to a scaled tag finally lands the way you meant it, which means anyone who worked around the old behavior has to stop. The full notes, with every setting, are on [the docs release page](https://docs.hotloop.io/releases/hotloop-4-19-2/).

Upgrading from 4.18.11 is a `helm upgrade` as usual, and Quadlet units follow `:stable` and need nothing. `helm rollback` to 4.18.11 is fine for this release, because the database is already PostgreSQL 17 and nothing here changes it.

What isn't proven. CODESYS was run against a real 4.22.0.0 runtime in the lab, not on a physical controller. OPC UA PubSub was proven against open62541 in both directions, and its subscriber read the [HotLoop Transmitter](/transmitter/) library publishing from a CODESYS runtime in a container. It has not been run against a Siemens or Beckhoff publisher, a physical controller, or across a router. No S7 or CIP server is on the wire in the lab, so the silent-PLC fix for those two is not shown against one.
