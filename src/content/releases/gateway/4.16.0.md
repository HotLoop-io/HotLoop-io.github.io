summary: "The first published release since 4.3.1. Everything from 4.4.0 to 4.15.3 ships at once, under the HotLoop name, with the Edge Relay beside it."
highlights:
  - "Entities. Every tag is an entity with an id that never changes, placed on one ISA-95 equipment tree. A motor, a valve or a PID loop is one entity built from its tags, every alarm is an entity, and every entity command goes through the same write gate as a tag write. MCP, automations and the new Entities and Plant screens all use them."
  - "Ask before you send. A service call takes ?dry_run=true and answers with the refusal the real call would give, word for word, and the command prompt says \"Would be refused: ...\" before anybody confirms."
  - "Paging that reaches a phone: ntfy and a Discord bot with an Acknowledge button, Gotify, and Discord webhooks, on rate limits that fold a flood into one summary instead of dropping alarms."
  - "Fixes that matter on a running plant. Unshelve could wipe an unacknowledged alarm. An OPC UA subscription could go silent forever while the session said connected. A silent Modbus device took up to 15 minutes to go down, and takes about 11 seconds now. A failed webhook logged its URL, which for Discord and ntfy is the password."
  - "Ignition 8.3.9 reads the OPC UA server, verified end to end, and the certificate survives a redeploy now, so Ignition stops distrusting it every time the pod moves."
  - "The Edge Relay ships as its own image and chart, released in lockstep with the Gateway. TimescaleDB 2.30.1, and the extension updates itself on start."
  - "Images: ghcr.io/hotloop-io/hotloop:4.16.0 and ghcr.io/hotloop-io/hotloop-edge-relay:4.16.0, for amd64 and arm64, pulled with no login. Charts hotloop and hotloop-edge-relay 4.16.0 from https://hotloop.io/hotloop, and a Quadlet unit for the Edge Relay."
breaking:
  - "Coming from 4.3.1 it is not a plain helm upgrade. The image is ghcr.io/hotloop-io/hotloop (was ghcr.io/embernet-ai/industrial-iot), the chart is hotloop from https://hotloop.io/hotloop (was industrial-iot), and every IIOT_ variable is HOTLOOP_. The chart name is in the workload selectors, so keep the release name and namespace, pg_dump first, delete the old Deployment and StatefulSet (the database volume stays), then helm upgrade with your old values file, IIOT_ renamed and any image.repository override dropped, not --reuse-values. Checked by rendering both charts side by side, not on a live cluster, which is what the pg_dump is for."
  - "License: the HotLoop Community License v1.0, not Apache-2.0. Free for individual, home, hobbyist, nonprofit and education use. Businesses sign up free through EmberNET."
  - "There is a login, writes default to off, and a timezone that won't load stops startup instead of running on UTC."
  - "API: empty lists are [], never null. History buckets with no good reading are null. An error the API can't place is a 500 with a log ref, and a device that errors on a write or a browse is a 502. alarm.turn_on is a 400, unshelving an alarm that isn't shelved is a 409, and tag JSON always carries minValue, maxValue and hasRange."
