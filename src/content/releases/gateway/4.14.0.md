summary: "Scheduled reports: historian numbers, crunched on a schedule and delivered as CSV or HTML, by email if you want."
highlights:
  - "A report names its tags, a window (the previous 24 hours, the previous calendar day, or the previous 7 days), a bucket (the whole window, per hour, or per day), and the aggregations: min, max, avg, first, last, and count. It runs on an interval, daily at a time, or weekly on a weekday at a time."
  - "Schedules are wall-clock times in the plant timezone and are computed as calendar dates, never by adding 24 hours, so a 03:00 report still runs at 03:00 the day after the clocks change."
  - "Only good-quality readings are aggregated, and every row says how many it left out. A tag with no readings in a period says no data. It never says zero."
  - "A run missed while the Gateway was down runs once on start-up, not once per missed slot. A report with recipients and no mail relay records a failed run instead of a quiet success."
  - "Viewers read reports, operators run them, and only admins define them, because a definition decides who receives plant data."

API only, and CSV and HTML only. There is no screen and no PDF in this version. Report definitions and run records are in the database backup, and the output files are not.
