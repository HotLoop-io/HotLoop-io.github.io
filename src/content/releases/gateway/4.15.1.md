summary: "Device credentials are hidden from every role, for every protocol, and scrubbed out of every log and error that could repeat them."
highlights:
  - "Before this, any logged-in user, viewers included, could read a device's MQTT broker password, its HTTP and MTConnect credentials, and anything else saved in it through the devices API. Every credential a driver reads now comes back as [redacted], to a viewer, an operator, and an admin alike."
  - "That covers passwords, header values, a body that mentions a credential, and the user info or token inside an address like mqtt://user:pass@broker or ?api_key=. Any key named like a secret is hidden by default, even one no driver reads yet."
  - "Saving [redacted] back, or leaving the key out, keeps the stored value. A device cannot be pointed at a new host while keeping its stored credentials, because the Gateway would hand them to the new host."
  - "A device's last error, the system log, the write audit table, the process log, the MCP tools, the diagnostics endpoint, and site errors are all scrubbed of credentials by value and by shape."
breaking:
  - "Anyone editing a device now sees [redacted] in the secret fields and has to type a secret to change it."

If untrusted users could reach a Gateway running an unreleased build before this fix, rotate the device credentials it holds. There has been no public release since 4.3.1. Backups, the Edge Relay's device file, and fleet config push still carry credentials as stored, because the drivers need them.
