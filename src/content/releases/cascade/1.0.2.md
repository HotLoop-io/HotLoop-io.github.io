The reason is a public form that checks a proof of work with an HMAC. Before this, the only way to do that in a workflow was to put the key in an item or a variable, and both end up in stored runs or in plain text. Now the key is a credential and the stored run has the signature and nothing else.

What isn't proven: the full local suite did not run for this release. Only the targeted tests ran (the Code step's helpers and credential, the webhook's CORS settings and preflight, and the catalog and workflow packages), all passing on The Beast, because the lab's MQTT broker would not start on that box.

Upgrade with `helm upgrade` to 1.0.2, or let `:stable` roll the Quadlet units. Workflows that never touch the new helpers behave exactly as before. A workflow that calls a new helper fails on 1.0.1 with the helper undefined, so put 1.0.1 back only for the others.
