If you give an agent a Cascade API key, 1.2.0 finishes what it can do with it. The four routes that a key was always allowed to call, and that the MCP server had left out, are tools now, so an agent can list and revoke keys, open a test webhook for a workflow, and start an OAuth2 sign-in that a person then confirms.

Upgrade with `helm upgrade` to 1.2.0, or let `:stable` roll the Quadlet units. Nothing in the database changes, so putting 1.1.1 back is safe. What a rollback cannot undo is what an agent already did with the new tools.
