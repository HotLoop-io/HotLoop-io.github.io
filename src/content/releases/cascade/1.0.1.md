highlights:
  - "A session check, an API key, a SCIM token, and a key's user used to read a database that blinked as an invalid login and answer 401, and the session check also cleared the cookie, so a short outage signed everyone out. A store that cannot be read now answers 503 with a Retry-After and the cookie stays."
  - "The second factor had the same flaw: during an outage a good authenticator code, recovery code, or passkey was answered as a wrong code, which can lock a person out of their own account. Those steps answer 503 for a store or server error and keep 401 for a real refusal."
  - "Tests for each of these fail on 1.0.0 and pass on 1.0.1. There are no migrations."

If you run Cascade behind sign-in, this is the update that stops a database hiccup from logging the whole plant out. Nothing else changed from 1.0.0.

Upgrade with `helm upgrade` to 1.0.1, or let `:stable` roll the Quadlet units. Nothing in the database changes, so putting 1.0.0 back is safe. A backup before any update is still the right habit.
