From 2.1.0 it's a plain image bump, with no migration and no flag, and a flows.json that ran on 2.1.0 runs on 2.2.0. The first start creates state.db in the data directory. Going back to 2.1.0 leaves it where it is, because 2.1.0 has no code that reads it. Every write to state.db is a write to an SD card or an SSD, so context changes are batched and a hard kill can lose up to 30 seconds of them.

It has never run on a real plant floor. The S7 and EtherNet/IP nodes have not met a Siemens CPU or a Logix controller, durable wires have never been on a Pi, and Modbus RTU, Modbus over TLS and OPC UA events, history and browse are not done. The full notes, with every new setting, are on [the GitHub release](https://github.com/HotLoop-io/hotloop-flow/releases/tag/v2.2.0).
