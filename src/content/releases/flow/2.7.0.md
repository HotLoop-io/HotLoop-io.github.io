This is the first cut of FlowLab, and it is not all of it. A diagram is a tab where every node runs once, when each wired input has a value, which is what a test bench or a data logger needs: a loop that carries state, an error that travels on a wire of its own, a panel you can open on a phone, and a debugger that can pause a run and show what is on every wire. Flows run exactly as they did, and a flow file you have today loads and saves byte for byte.

The image is amd64 only for this release. I build amd64 first, let it read stable in production, and then one small 2.7.1 with nothing else in it adds arm64. Until then the `2` tag holds the new amd64 image and the arm64 image from 2.6.0, so a box on arm64 that follows `2` or `2.6` keeps what it has. A plain `helm upgrade` is the upgrade on amd64, there is nothing to migrate, and the one new permission, `diagram.run`, matters only if your users have explicit permission lists.

What is not here yet: a case structure, records and shared types, waveforms, TDMS and binary logs, a database or MQTT write, instrument and data acquisition nodes, filters and statistics, sub-diagrams, serial flow control, and checks for diagrams in `hotloop-flow test`. It has been run against a program that writes scale frames on a pseudo terminal, not a physical scale, and not for a day on a Pi. FlowLab does not do hard real time: work with a deadline belongs in a PLC.
