If you run Flow behind the EmberCORE dashboard, this is the one that gets rid of the second login. Someone opens Flow from the dashboard and they are in, with the role their tenant gave them, full access or read-only. A viewer cannot deploy, and nobody has to remember a Flow password.

If you don't, nothing happens. With no key file Flow does not read the header at all, so a plain image bump from 2.3.0 changes nothing on first start. The chart takes the whole thing under embernetSignin, the App Store hands it the dashboard's public key, and the chart mounts it, writes the settings, rolls the pod, and annotates the Service so the dashboard knows to sign people in.

To use it by hand, mount the dashboard's public key (a PEM file) and set auth.assertion.publicKeyFile and auth.assertion.audience, or HOTLOOP_FLOW_ASSERTION_PUBLIC_KEY_FILE and HOTLOOP_FLOW_ASSERTION_AUDIENCE. Flow refuses to start with a key it can't read or with no audience, because a half-configured sign-in that quietly lets everyone through is worse than one that won't boot. The other settings are auth.assertion.issuer, header and hideLogin.

It has not run behind the live dashboard, in a Fleet install, or in a person's browser outside the CI suite. It ran against a real Flow binary behind a signer built from the dashboard's own code, with every refusal exercised and the websocket handshake checked. Treat the first real install as the test that matters. The full notes are on [the GitHub release](https://github.com/HotLoop-io/hotloop-flow/releases/tag/v2.4.0).
