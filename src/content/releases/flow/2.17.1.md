HotLoop Flow 2.17.1 makes the flows you bring over from Node-RED and the VIs you bring over from LabVIEW behave the way they did where they came from, and lets you ask a running Flow which build it is. Nothing in your flows, settings or chart changes.

## What changed

- **A Function node can use the names Node-RED lets it use.** A body that declares its own `const context`, `flow`, `global`, `env` or `util` used to fail to compile and the node did not start. It now runs as it did in Node-RED.
- **The CSV node says which columns it used.** After it reads or writes a table, `msg.columns` holds the column names, so a flow that adds a column between a read and a write keeps every column. A column list typed into the node comes first.
- **`hotloop-flow version` names the commit** the image was built from, after the version number.
- **Proved on more than the examples.** All 425 VIs of NI's published icon editor project are read, each with exactly the wires an independent reader finds, and 22 of the 24 comparable flows from the public Node-RED library give the same output on Flow and on Node-RED 5.0.10.

## Upgrade

A plain `helm upgrade` to the 2.17.1 image and chart, or the new tag in your Quadlet unit. Nothing needs migrating. 2.17.0 was never published: its image build stopped at its own check before pushing anything, so 2.17.1 is the first of this line. A CSV node that has its own columns typed in and also receives `msg.columns` now uses the typed ones.
