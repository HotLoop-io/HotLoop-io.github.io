From 2.2.0 it's a plain image bump, with no migration and no flag, and a flows.json and config file that ran on 2.2.0 run on 2.3.0. A flow with no schemas anywhere behaves exactly as it did, and a write node with no HotLoop picked writes the way it did in 2.2.0. Going back to 2.2.0 is safe for any flow that doesn't use the new nodes. A HotLoop, MCP or plugin node fails to start there, and a write node with a HotLoop picked writes straight to its equipment on 2.2.0, so take the HotLoop off those nodes before you go back.

MCP is a new way into Flow and it takes a token. Nothing is served until a flow has an mcp tool node, and a call with no token or a made-up one is refused. Plugins are off until you give the runtime a trusted key, and the chart takes all of it under plugins with enabled false by default.

It has never run on a real plant floor. Only the Modbus write was run through a real HotLoop gate, on the published HotLoop 4.18.10 image in CI. The OPC UA, S7 and EtherNet/IP writes send through the same code. The S7 and EtherNet/IP nodes have still only met simulators. The HotLoop reconnect is tested against a stand-in, MCP has no OAuth, stdio, resources, prompts, or sampling, and plugins have never run on a Pi. The schema validator is not Ajv: it refuses a $ref outside the schema and ignores format values it doesn't know. Flow now has Raspberry Pi 5 numbers, and a Pi 4, a Zero 2 W and SD card writes are still not measured. The full notes, with every new setting, are on [the GitHub release](https://github.com/HotLoop-io/hotloop-flow/releases/tag/v2.3.0).
