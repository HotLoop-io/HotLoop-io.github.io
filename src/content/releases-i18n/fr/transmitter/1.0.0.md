Ajoutez la bibliothèque, déclarez un bloc fonctionnel, ajoutez les variables à sortir et appelez-le une fois par cycle. Tout ce qui s'abonne à OPC UA PubSub peut le lire, HotLoop compris.

La bibliothèque se compile avec 0 erreur et 0 avertissement dans CODESYS 3.5.22.30. L'abonné de HotLoop core (depuis la branche principale de core au moment de ce test, et dans HotLoop core 4.19.4 et chaque version suivante) lit les deux éditeurs, y compris la chaîne, le TIME, les deux tableaux et deux compteurs qui bougent. Un second décodeur Go lit les 222 datagrammes capturés. Le bloc ajoute en moyenne environ 10,6 microsecondes par cycle sur une tâche de 20 ms, un cycle qui envoie coûte de 10 à 100, et l'envoi le plus long sur 12 000 cycles a pris 14,3 ms sur un hôte partagé très chargé, donc placez l'éditeur dans sa propre tâche de priorité plus basse si cela compte pour la logique de votre commande.

Ce qui n'a pas été testé : aucun automate physique, aucun runtime autre que Control for Linux SL 4.22.0.0, aucun CPU autre que x86-64, le multicast, un runtime qui perd et retrouve son réseau, la fin de la fenêtre de démonstration de deux heures, et des récepteurs autres que les quatre ci-dessus.

Pas dans cette version : les horodatages, KeepAlive et Delta Frames, plus d'un DataSetMessage par NetworkMessage, WSTRING, un statut par champ, la sécurité des messages et le côté abonné. Un récepteur qui exige un horodatage, un KeepAlive ou un Delta Frame ne sera pas satisfait par cette version.

Téléchargez `HotLoopTransmitter-1.0.0.library` depuis [hotloop.io/hotloop-transmitter/1.0.0/](https://hotloop.io/hotloop-transmitter/1.0.0/HotLoopTransmitter-1.0.0.library), vérifiez-la avec `SHA256SUMS` dans le même dossier, et installez-la avec Tools, Library Repository, Install dans CODESYS 3.5 SP22 ou ultérieur. Le `.compiled-library` est la même bibliothèque sans son source. La [page d'installation](https://docs.hotloop.io/transmitter/install/) contient le reste.
