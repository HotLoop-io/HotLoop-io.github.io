添加该库，声明一个功能块，添加您想输出的变量，并在每个周期调用它一次。任何订阅 OPC UA PubSub 的东西都能读取它，包括 HotLoop。

该库在 CODESYS 3.5.22.30 中构建时 0 个错误、0 个警告。HotLoop core 的订阅者（来自这次测试时 core 的主分支，以及 HotLoop core 4.19.4 及其之后的每个版本）能读取两个发布者，包括字符串、TIME、两个数组和两个在变化的计数器。第二个 Go 解码器读取了全部 222 个捕获的数据报。在 20 ms 任务上，该块平均每个周期增加约 10.6 微秒，发送的周期要花 10 到 100，而在 12000 个周期中最长的一次发送在一台繁忙的共享主机上用了 14.3 ms，所以如果这对您的控制逻辑很重要，请把发布者放在它自己的较低优先级任务中。

没有运行的内容：任何物理控制器，除 Control for Linux SL 4.22.0.0 之外的任何运行时，除 x86-64 之外的任何 CPU，多播，丢失并重新获得网络的运行时，两小时演示窗口结束时的情形，以及上述四种之外的接收方。

不在这个版本中的内容：时间戳，KeepAlive 和 Delta Frame，每个 NetworkMessage 多于一个 DataSetMessage，WSTRING，每个字段的状态，消息安全，以及订阅者一侧。坚持要求时间戳、KeepAlive 或 Delta Frame 的接收方无法被这个版本满足。

从 [hotloop.io/hotloop-transmitter/1.0.0/](https://hotloop.io/hotloop-transmitter/1.0.0/HotLoopTransmitter-1.0.0.library) 下载 `HotLoopTransmitter-1.0.0.library`，用同一文件夹中的 `SHA256SUMS` 校验，并在 CODESYS 3.5 SP22 或更高版本中通过 Tools、Library Repository、Install 安装。`.compiled-library` 是同一个库，只是不含源代码。其余内容见[安装页面](https://docs.hotloop.io/transmitter/install/)。
