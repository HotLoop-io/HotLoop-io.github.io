HotLoop Flow 2.16.0 把一个流程文件推送到租户运行的每一个 Flow 安装，并让两个安装共享一项工作，同一时间只有其中一个向设备写入。它先发布 amd64，arm64 在 2.16.1 中跟进。

## 新增内容

- **推送到租户的站点。** 一个流程文件连同它的 FlowLab 图表，逐台送到 EmberNet 显示为该租户正在运行的每个 Flow 安装。每次部署后，站点必须回答所有站点都应有的修订版本，启动每个节点，并且图表存在且正在运行。失败的站点会被放回它原来所在的部署，推送随即停止。会重启正在运行的记录器的推送，会等待一个确认。
- **带 fencing lease 的热备。** 两个安装在一个 PostgreSQL 中共享一个 lease。每次向设备写入都先检查它，涵盖 Modbus、S7、OPC UA 和 EtherNet/IP 的写入节点、HotLoop 的脚本和配方节点，以及 FlowLab 图表的写入。备用，或已失去 lease 的持有者，其写入会在任何内容发出之前被拒绝，备用在活动安装的 lease 到期后接管。
- **同样的功能也可通过 API 和 MCP 工具使用，** 使 Flow 自己的工具达到 44 个，并为两者提供 chart 取值和 Quadlet 行。

## 升级

直接 `helm upgrade` 到 2.16.0 的镜像和 chart，或者在您的 Quadlet 单元里换成新标签。首次启动不会发生任何事，也不需要迁移。这两项功能在您设置之前都是关闭的，流程文件的加载和保存与以前逐字节一致。

## 尚未证实的内容

推送是在一台实验室机器上对真实的 Flow 安装运行的，用一个替身代替仪表板，没有通过 Flux 推送到真实租户。备用是作为两个真实的 Flow 进程，对着真实的 PostgreSQL 和一个 Modbus 服务器运行的，没有对着真实的 PLC，所以不清楚 PLC 对写了两次的设定值会怎样处理：请写入设定值，不要写入增量。lease 下的数据库故障切换没有试过。chart 取值和 Quadlet 行只是渲染过，没有在集群上运行过。
