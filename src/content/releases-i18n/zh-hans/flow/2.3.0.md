从 2.2.0 起这是一次简单的镜像升级，没有迁移，也没有开关，在 2.2.0 上运行的 flows.json 和配置文件在 2.3.0 上照常运行。任何地方都没有 schema 的流程，行为和以前完全一样，没有选择 HotLoop 的写入节点，写入方式与 2.2.0 相同。对任何不使用新节点的流程，退回 2.2.0 都是安全的。HotLoop、MCP 或插件节点在那里无法启动，选择了 HotLoop 的写入节点在 2.2.0 上会直接写入它的设备，所以退回之前，请先把这些节点上的 HotLoop 去掉。

MCP 是进入 Flow 的新入口，需要令牌。在流程里有 mcp tool 节点之前，什么都不会对外提供，没有令牌或用编造的令牌发起的调用会被拒绝。插件在您给运行时一个受信任的密钥之前是关闭的，chart 把整个功能放在 plugins 之下，enabled 默认为 false。

写入节点通过 HotLoop 的写入闸发送，这个闸已用 Modbus 写入做过端到端的运行。schema 校验器不是 Ajv：它会拒绝 schema 之外的 $ref，并忽略它不认识的 format 取值。Flow 现在有了 Raspberry Pi 5 的数据。包含每项新设置的完整说明见 [GitHub 发布页](https://github.com/HotLoop-io/hotloop-flow/releases/tag/v2.3.0)。
