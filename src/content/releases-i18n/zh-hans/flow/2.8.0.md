HotLoop Flow 2.8.0 给 FlowLab 新增了四样东西，FlowLab 是用于试验台和数据记录器的图表标签页：分析节点、用于 NI 硬件的数据采集节点、会保留代理漏掉消息的 MQTT 输出，以及 TDMS 日志。流程的运行与之前完全一样，您现在拥有的流程文件逐字节加载和保存，不是图表的标签页也看不到其中任何内容。

## 新功能

**分析。** 四个节点作用于一个读数数组：统计（平均值、均方根、最小值、最大值和标准差）、积分（用梯形法则求数组下方的面积，输出一个数，或输出累计面积）、微分（每个样本处的斜率），以及 1 到 10 阶的巴特沃斯滤波器，可用作低通、高通、带通或带阻，截止频率以赫兹为单位。结果已与手工算出的值核对过。

**数据采集节点。** `read DAQ task` 通过 NI 的 gRPC 设备服务器，从 CompactDAQ 机箱之类的 NI 硬件读取样本。客户端做得尽可能小：用 Go 自带的 HTTP/2 加手写的消息，所以二进制文件没有引入 gRPC 库。NI 公布的协议定义放在 `third_party/ni-grpc-device`，遵循其许可证，并在 NOTICE 中附有说明。

**不丢任何消息的 MQTT 输出。** `mqtt out` 通过流程文件所配置的代理发布，与 MQTT 节点使用的是同一个连接。把它标为持久，代理漏掉的消息会在节点结束之前写入磁盘，并在代理恢复后按先到先发的顺序发送，即使中间重启过也一样。没有任何消息会越过排在它前面的消息。它的已发送输出会告诉您这条消息是否直接发出。

**TDMS 日志。** `log to TDMS file` 向 TDMS 文件追加一条记录，每个字段一个通道，这个文件可以在实验室已有的工具里打开。读取器和写入器依据 NI 公开的格式文档编写。最后一次写入被断电打断的文件，仍然可以读到最后一个完整的值。

## 变更内容

- 调色板的 FlowLab 部分现在有 28 种节点类型，原来是 21 种，README 也这样写。
- 2.7.1 的那次运行中有一个步骤失败过一次，却没有输出任何内容，原因是收集器测试在它所读取的日志还没包含整段时间之前就比较了这一段；现在它会等整段时间。另外两个测试也改成了等待它们所检查的内容。这些都不会随版本发布。
- README 的图片重新截取，让顶部栏显示 v2.8.0。
- README 中的二进制文件和镜像大小针对这次发布重新读取过。

## 升级

在 amd64 上，只需对 2.8.0 的镜像和 chart 执行一次 `helm upgrade`，或在您的 Quadlet 单元里换上新标签。在 arm64 上，请先保持现状，等到 2.8.1，它就是加上 arm64 的这个版本，仅此而已。首次启动时不会发生任何事，也不需要迁移。
