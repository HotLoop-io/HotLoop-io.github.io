4.23.2 在 CODESYS PLC、HotLoop 和 EmberNet 仪表板之间形成闭环，并清扫了测试套件中慢节点的失败，每一个都是真实的等待或竞争，已被修复。

## 变更内容

- **CODESYS 可视化可作为画面导入。** 从 IDE 以原生导出文件导出，仪表板画面上的导入就会读取它。对不可写入标签的按钮或设定值会被拒绝，与构建时一样。
- **面向 EmberNet 仪表板的盒子健康状况。** 以 Kubernetes 节点命名的设备会发布盒子的 CPU、内存、磁盘和数据卷使用情况，以及当代理为它写入文件时三个核心的实时抖动。OPC UA 服务器提供它们的历史。
- **一个只能读取、别的什么都不能做的登录。** chart 在首次安装时为仪表板创建一个，升级时从不轮换。仪表板的证书从 Secret 获得信任，30 秒内加入，离开时移除，服务器仍然只接受不带匿名会话的 Basic256Sha256 SignAndEncrypt。
- **Energy 增加需量电费和班次。** 电表接受窗口内最高一刻钟每千瓦的价格，摘要显示峰值、开始时间，以及那一刻钟里读到了多少。已创建但什么都没统计的单位成本，会带原因地什么也不读，而不是免费。
- **套件发现的修复：** 能源引擎不再读取正在删除的电表，备份的清单会就地改名，所以列表绝不会看到半个文件，历史库的追赶会等到把一个标记之前的所有内容写完。

## 盒子健康状况默认开启

chart 以只读方式挂载主机的根目录及其 `/proc`，不增加任何权限。强制执行限制性 Pod Security 配置的集群会拒绝主机路径，在那里盒子健康状况或它的主机挂载会被关闭，盒子的磁盘和 CPU 读为坏，并说明需要挂载什么。

## 升级

一次迁移，`0030_energy_demand`，只添加一个默认值为 0 的列。直接 `helm upgrade` 会在首次启动时运行它。这个版本构建 amd64 镜像，多架构构建作为下一个版本跟上。

## 尚未证明的部分

- CODESYS 导入在实验室 IDE 的一个可视化上得到证明，来自其他项目的画面可能列出更多无法放置的元素。
- 盒子健康状况在实验室节点上运行过，抖动标签需要一个写入该文件的代理，而这个版本并不安装它。
- 只读登录和证书信任是用 HotLoop 自己的客户端证明的。EmberNet 仪表板那一侧是它自己的版本。
- 需量电费是用记录下来的读数核对的，而不是用电力公司的账单。
