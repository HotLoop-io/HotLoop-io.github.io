값이 언제 샘플링되었는지 알고 싶은 구독자는 이제 도착 시점으로 추측하는 대신 패킷에서 그것을 얻으며, 라이브러리는 다른 추가 기능처럼 CODESYS Installer로 설치할 수 있습니다.

타임스탬프를 켠 두 퍼블리셔, Variant와 RawData에서 모든 값이 PLC가 자체 OPC UA 서버로 보고하는 값과 같았습니다. HotLoop core의 구독자는 이 테스트를 실행했을 때의 main 브랜치와 HotLoop core 4.19.4 및 이후 모든 릴리스에서 두 퍼블리셔를 읽으며, 모든 읽기값이 퍼블리셔의 타임스탬프를 시각으로 가집니다. 패키지는 PackageManagerCLI로 설치되고 예제는 그것을 대상으로 빌드됩니다. 퍼블리셔가 둘인 20 ms 태스크에서 블록은 사이클당 평균 약 9.6마이크로초를 더하며, 실행 중 가장 긴 사이클은 81마이크로초였습니다.

실행하지 않은 것: 모든 물리 컨트롤러, Control for Linux SL 4.22.0.0 외의 모든 런타임, 실시간 시계가 설정되지 않았거나 틀린 컨트롤러(블록은 시계가 말하는 값을 스탬프합니다), IDE 자체의 Package Manager 창에서의 패키지, 멀티캐스트, 네트워크를 잃었다가 되찾는 런타임, 그리고 2시간 데모 기간의 끝.

이번 릴리스에 없는 것: KeepAlive와 Delta Frame, NetworkMessage당 둘 이상의 DataSetMessage, WSTRING, 필드별 상태, 1초 미만의 타임스탬프, 메시지 보안, 구독자 쪽. 1.0.0에 고정한 PLC 프로젝트는 계속 동작하며 계속 1.0.0 바이트를 보냅니다.

`HotLoopTransmitter-1.1.0.library`, `.compiled-library`, `.package`를 [hotloop.io/hotloop-transmitter/1.1.0/](https://hotloop.io/hotloop-transmitter/1.1.0/HotLoopTransmitter-1.1.0.library)에서 내려받아 같은 폴더의 `SHA256SUMS`로 확인하고, [설치 페이지](https://docs.hotloop.io/transmitter/install/)를 참고하세요.
