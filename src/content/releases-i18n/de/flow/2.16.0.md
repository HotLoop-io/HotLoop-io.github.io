HotLoop Flow 2.16.0 schickt eine Flow-Datei an jede Flow-Installation, die ein Mandant betreibt, und lässt zwei Installationen sich eine Aufgabe teilen, wobei immer nur eine auf die Anlage schreibt. Es erscheint zuerst für amd64, arm64 folgt mit 2.16.1.

## Neu

- **Push an die Stationen eines Mandanten.** Eine Flow-Datei geht samt ihren FlowLab-Diagrammen nacheinander an jede Flow-Installation, die EmberNet für den Mandanten als laufend zeigt. Nach jedem Deploy muss die Station die Revision melden, die alle Stationen haben sollen, jeden Node starten und ihre Diagramme vorhanden und laufend haben. Eine Station, die scheitert, wird auf das Deployment zurückgesetzt, auf dem sie war, und der Push stoppt. Ein Push, der einen laufenden Logger neu starten würde, wartet auf ein Ja.
- **Ein Warm-Standby mit Fencing-Lease.** Zwei Installationen teilen sich einen Lease in einer PostgreSQL. Jeder Schreibzugriff auf die Anlage prüft ihn zuerst, in den Schreib-Nodes für Modbus, S7, OPC UA und EtherNet/IP, den Skript- und Rezept-Nodes von HotLoop und den Schreibvorgängen der FlowLab-Diagramme. Einem Standby oder einem Halter, der seinen Lease verloren hat, wird der Schreibvorgang abgewiesen, bevor etwas gesendet wird, und der Standby übernimmt, wenn der Lease der aktiven Installation abläuft.
- **Dasselbe über die API und als MCP-Tools,** womit die eigenen Tools von Flow auf 44 kommen, und Chart-Werte und Quadlet-Zeilen für beides.

## Upgrade

Ein einfaches `helm upgrade` auf das Image und Chart 2.16.0, oder der neue Tag in Ihrer Quadlet-Unit. Beim ersten Start passiert nichts, und es muss nichts migriert werden. Beide Funktionen sind ausgeschaltet, bis Sie sie einrichten, und eine Flow-Datei wird Byte für Byte wie bisher geladen und gespeichert.

## Was nicht belegt ist

Der Push lief gegen echte Flow-Installationen auf einer Labormaschine, mit einem Ersatz für das Dashboard, und nicht über Flux zu einem echten Mandanten. Der Standby lief als zwei echte Flow-Prozesse gegen eine echte PostgreSQL und einen Modbus-Server, und nicht gegen eine echte PLC, daher ist nicht bekannt, was eine PLC mit einem doppelt geschriebenen Sollwert macht: Schreiben Sie Sollwerte, keine Inkremente. Ein Datenbank-Failover unter dem Lease wurde nicht versucht. Die Chart-Werte und Quadlet-Zeilen wurden gerendert und nicht auf einem Cluster ausgeführt.
