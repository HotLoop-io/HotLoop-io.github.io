HotLoop Flow 2.13.0 benachrichtigt Menschen und Kafka, macht mehr von FlowLab fertig und verhindert, dass ein Deploy einen unveränderten Lauf neu startet. Es bringt fünf Knoten, die senden, was eine Nachricht trägt (ntfy, Gotify, ein Discord-Webhook, ein Discord-Bot, Kafka), ein Intensitätsdiagramm, Flusssteuerung am seriellen Port und Diagrammtests, die Sie in CI laufen lassen können. Nichts, was Sie haben, ändert sich, solange Sie die neuen Teile nicht nutzen, außer dass ein Deploy ein Diagramm, das Sie nicht angefasst haben, nicht mehr neu startet.

## Neu

- **Benachrichtigungsknoten.** `ntfy out`, `gotify out`, `discord out` (ein Webhook) und `discord bot out`, mit Konfigurationsknoten, die dieselben Einstellungen nehmen, mit denen HotLoop core seine Alarme sendet: ein ntfy-Server und ein Token oder ein Login (oder keines bei einem Server, auf dem jeder veröffentlichen darf), ein Gotify-Anwendungstoken, eine Discord-Webhook-URL, ein Discord-Bot-Token und ein Kanal. Sie senden `msg.payload`, nehmen Titel, Topic, Priorität, Kanal oder Farbe aus dem Knoten oder aus der Nachricht, wenn der Knoten sie leer lässt, und geben die Nachricht weiter. Kein Geheimnis steht in einem Fehler, Status oder Log: Eine Discord-Webhook-URL ist die ganze Zugangsberechtigung, ein ntfy-Topic auf einem öffentlichen Server ebenfalls, und selbst ein Netzwerkfehler, der die Adresse nennt, wird bereinigt. Eine Ablehnung behält den eigenen Grund des Servers. Ein Ratenlimit wird einmal abgewartet, so lange der Server es verlangt und höchstens eine Minute, danach schlägt die Nachricht fehl. Discord-Inhalt wird bei 2000 Zeichen und die Beschreibung eines Embeds bei 4096 gekürzt, gezählt, wie Discord zählt, und nichts in einer Nachricht kann jemanden anpingen. Kein Slack und kein Teams.
- **Kafka out.** `kafka out` mit einem Konfigurationsknoten `hotloop-flow-kafka`: Broker, SASL PLAIN oder SCRAM-SHA-256 oder SCRAM-SHA-512, TLS. Es schreibt `msg.payload` mit einem optionalen Schlüssel in ein Topic, als Text oder als JSON, wenn es kein Text ist, und gibt die Nachricht weiter, sobald der Cluster sie von jedem synchronen Replikat bestätigt hat. Es nutzt franz-go, den Client, den auch die Kafka-Ausgabe von HotLoop core verwendet, sodass alles antwortet, was die Kafka-API spricht. Dadurch wird die Binärdatei etwa 5,5 MB größer (48 083 106 Bytes, vorher 42 598 562 in 2.12.1, gebaut mit `CGO_ENABLED=0 -trimpath -ldflags="-s -w"`).
- **Intensitätsdiagramm.** Der Modus eines Diagramms kann `intensity` sein. Er nimmt ein Array aus Zahlenzeilen, bis zu 512 mal 512, zeichnet jeden Wert als Farbe vom kleinsten bis zum größten und ersetzt das Bild mit jedem Raster. Ein flaches oder ungleichmäßiges Array ist ein Fehler auf der Fehlerverbindung des Knotens.
- **Serielle Flusssteuerung.** `dia-serial-open` hat eine Einstellung `flow` (none, rtscts, xonxoff), und eine Geräteadresse `serial://` nimmt `flow=`. Sie wird am Terminal gesetzt, nachdem der Port geöffnet ist, sodass ein Port, der nach einem gezogenen Kabel erneut geöffnet wird, sie wieder bekommt, und none löscht, was ein anderes Programm hinterlassen hat. Nur Linux: Auf jedem anderen System wird ein Diagramm, das mehr als none verlangt, abgelehnt, statt ohne die Einstellung zu laufen.
- **Diagrammtests.** Eine Flow-Testdatei kann einen Test eines FlowLab-Diagramms enthalten: Setzen Sie seine Bedienelemente nach Beschriftung oder ID, führen Sie es einmal aus und prüfen Sie seine Anzeigen (eine Zahl auf ein Millionstel genau oder `{min, max}`). Ein Diagramm mit einem Knoten, der aus dem Test hinausreichen würde (ein serieller Port, ein Messgerät, ein Datenerfassungsgerät, MQTT out, ein HotLoop-Schreibzugriff, eine Logdatei), wird abgelehnt.

## Was sich geändert hat

- **Ein Deploy behält einen unveränderten Lauf.** Ein Deploy stoppte früher jeden Diagrammlauf und startete die mit Autostart neu, sodass jedes Deployen den Logger eines Werks neu startete. Ein Lauf geht jetzt weiter, wenn sein Diagramm, jeder Körper, den er ausführt, und jeder Konfigurationsknoten genau das sind, was sie waren. Wo ein Knoten gezeichnet ist, gehört nicht dazu, sodass das Verschieben eines Knotens auf der Zeichenfläche nie etwas neu startet. Ein Diagramm, das sich geändert hat, wird gestoppt und, wenn es Autostart hat, wie bisher neu gestartet.
- Das Flow-Chart trägt `artifacthub.io/license: LicenseRef-EmberNet-Source-1.0`.
- Sonst verhält sich nichts anders als in 2.12.1. Der Editor und das Panel sind überall gleich, wo Sie die neuen Knoten, den Intensitätsmodus, die Flusssteuerung oder einen Diagrammtest nicht nutzen, was ein Vorher-nachher-Inventar des Editors an einem festen Flow zeigt.

## Upgrade

Ein einfaches `helm upgrade` auf das Image und Chart 2.13.0, oder der neue Tag in Ihrer Quadlet-Unit. Beim ersten Start passiert nichts, und es muss nichts migriert werden. Die neue Abhängigkeit ist einkompiliert: Das Image hat weiterhin keine Shell und läuft wie bisher. Diese Version kommt zuerst für amd64, der arm64-Build folgt in 2.13.1, sodass eine arm64-Box bis dahin auf 2.12.1 bleibt.
