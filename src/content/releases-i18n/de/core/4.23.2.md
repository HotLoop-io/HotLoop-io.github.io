4.23.2 schließt den Kreis zwischen einer CODESYS-SPS, HotLoop und dem EmberNet-Dashboard und räumt die Fehler langsamer Nodes in der Testsuite aus, jeder ein echtes Warten oder Wettrennen, das behoben wurde.

## Was sich geändert hat

- **Eine CODESYS-Visualisierung wird als Bild importiert.** Exportieren Sie sie aus der IDE als native Exportdatei, und Importieren im Bild Dashboards liest sie. Eine Schaltfläche oder ein Sollwert auf einem Tag, das nicht beschreibbar ist, wird abgelehnt, genau wie bei einem Build.
- **Boxzustand für das EmberNet-Dashboard.** Ein Gerät, das nach dem Kubernetes-Node benannt ist, veröffentlicht die Auslastung von CPU, Speicher, Datenträger und Datenvolumen der Box sowie den Echtzeit-Jitter dreier Kerne, wenn ein Agent die Datei dafür schreibt. Der OPC UA-Server liefert deren Verlauf.
- **Ein Login, das lesen kann und sonst nichts.** Das Chart legt beim ersten Install eines für das Dashboard an und rotiert es bei einem Upgrade nie. Das Zertifikat des Dashboards wird aus einem Secret vertraut, innerhalb von 30 Sekunden hinzugefügt und entfernt, wenn es geht, und der Server nimmt weiterhin nur Basic256Sha256 SignAndEncrypt ohne anonyme Sitzungen.
- **Energy bekommt einen Leistungspreis und Verschiebungen.** Ein Zähler nimmt einen Preis für ein Kilowatt seiner höchsten Viertelstunde in einem Fenster, und die Zusammenfassung zeigt die Spitze, wann sie begann und wie viel dieser Viertelstunde gelesen wurde. Ein Preis pro Einheit liest nichts, mit Begründung, wenn nichts gezählt wurde, nicht gratis.
- **Fehler, die die Suite fand:** Die Energie-Engine liest einen Zähler nicht mehr, während er gelöscht wird, das Manifest einer Sicherung wird an Ort und Stelle umbenannt, sodass eine Liste nie eine halbe Datei sieht, und das Aufholen des Historians wartet, bis alles bis zu einer Marke geschrieben ist.

## Der Boxzustand ist standardmäßig an

Das Chart bindet die Wurzel des Hosts und sein `/proc` schreibgeschützt ein und fügt keine Berechtigung hinzu. Ein Cluster, der das eingeschränkte Pod-Security-Profil durchsetzt, lehnt einen Host-Pfad ab, und dort wird der Boxzustand oder sein Host-Mount ausgeschaltet, und Datenträger und CPU der Box lesen schlecht und sagen, was einzubinden ist.

## Upgrade

Eine Migration, `0030_energy_demand`, die nur eine Spalte mit dem Standardwert 0 hinzufügt. Ein einfaches `helm upgrade` führt sie beim ersten Start aus. Diese Version baut das amd64-Image, und der Multi-Arch-Build folgt als nächste Version.

## Was nicht belegt ist

- Der CODESYS-Import wurde an einer Visualisierung aus der IDE des Labors belegt, und ein Bild aus einem anderen Projekt kann mehr Elemente auflisten, die er nicht platzieren konnte.
- Der Boxzustand lief auf den Nodes des Labors, und die Jitter-Tags brauchen einen Agenten, der die Datei schreibt, was diese Version nicht installiert.
- Das Nur-Lese-Login und das Zertifikatsvertrauen wurden mit HotLoops eigenem Client belegt. Die Seite des EmberNet-Dashboards ist eine eigene Version.
- Leistungspreise wurden an aufgezeichneten Messwerten geprüft, nicht an der Rechnung eines Versorgers.
