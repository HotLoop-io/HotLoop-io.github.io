highlights:
  - "Antes de esto, cualquier usuario con sesión iniciada, incluidos los observadores, podía leer a través de la API de dispositivos la contraseña del broker MQTT de un dispositivo, sus credenciales HTTP y MTConnect y cualquier otra cosa guardada en él. Ahora cada credencial que lee un controlador vuelve como [redacted], tanto para un observador como para un operador y un administrador."
  - "Eso abarca contraseñas, valores de cabecera, un cuerpo que menciona una credencial, y la información de usuario o el token dentro de una dirección como mqtt://user:pass@broker o ?api_key=. Cualquier clave con nombre de secreto se oculta por defecto, incluso una que ningún controlador lee todavía."
  - "Guardar de vuelta [redacted], o dejar fuera la clave, conserva el valor almacenado. Un dispositivo no puede apuntarse a un nuevo host conservando sus credenciales almacenadas, porque el Gateway se las entregaría al nuevo host."
  - "El último error de un dispositivo, el registro del sistema, la tabla de auditoría de escrituras, el registro de procesos, las herramientas MCP, el endpoint de diagnóstico y los errores del sitio se limpian de credenciales por valor y por forma."

Si usuarios no confiables pudieron llegar a un Gateway que ejecutaba una compilación sin publicar antes de esta corrección, rote las credenciales de dispositivos que guarda. No ha habido ninguna versión pública desde 4.3.1. Las copias de seguridad, el archivo de dispositivos del Edge Relay y el envío de configuración de la flota siguen llevando las credenciales tal como están almacenadas, porque los controladores las necesitan.
