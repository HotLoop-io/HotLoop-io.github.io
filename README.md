# hotloop.io

Source for [hotloop.io](https://hotloop.io), built with [Astro](https://astro.build) and published to GitHub Pages by a workflow on every push to `main`.

```
npm install
npm run dev       # http://localhost:4321
npm run build     # regenerates the social cards and icons, then builds to dist/
```

Node 22.12 or newer is required, and `.nvmrc` pins the version CI uses.

## How it is put together

- **Design tokens** live in `src/styles/tokens.css`, a vendored copy of `brand/tokens.css` in [HotLoop-io/HotLoop-io](https://github.com/HotLoop-io/HotLoop-io). CI fetches the canonical file and fails the build if the two differ, so change a value there first and then copy it here.
- **Fonts** are Inter Variable and JetBrains Mono, self-hosted through `@fontsource`. Nothing loads from a CDN.
- **Integrations data** is in `src/data`. `protocols.json` is written from the Gateway's protocol docs. `nodes.json` is generated from Flow's compatibility document with `node scripts/import-flow-compat.mjs <path to compatibility.md>`.
- **Release notes** are markdown files in `src/content/releases/<product>/<version>.md`. To add one, add a file. Each states whether it has actually been published, and the page prints that.
- **Social cards and icons** are generated by `scripts/og.mjs` with all text converted to outlines, so nothing depends on a font being installed on the build machine.

## Two rules the build enforces

`astro build` fails if a protocol claims to be verified live and names nothing it was verified against, if one claims decode-tested and does not say what is unverified, or if a Flow node is anything short of full compatibility and does not say what is different. The site cannot claim more than the repositories behind it do.

## Writing

No em-dashes as connectors, Oxford commas, American spelling. The reasoning is in the [brand standard](https://github.com/HotLoop-io/HotLoop-io/blob/main/brand/BRAND.md).
